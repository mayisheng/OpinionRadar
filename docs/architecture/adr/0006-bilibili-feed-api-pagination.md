# ADR-0006：B 站动态流滚动到底后改用 API 分页突破限制

- 状态：Accepted
- 日期：2026-10-11

## 背景

迭代 001 的 `archive` 回溯归档依赖「页面滚动 → 拦截 feed/space 响应」的链路。
实测发现：B 站空间动态页滚动到底部后，页面不再自动加载更早内容，
但接口仍返回 `has_more=True`，说明服务器端还有更多数据，只是前端不再请求。

这导致 `archive` 命令在抓取 2026 年 1 月至今的内容时，只能抓到 8 月 10 日以来的 13 条，
1–7 月的内容完全缺失。`discover` 探测也受同样限制。

## 决策

在 `BilibiliBrowser._scroll_and_collect` 中增加 **API 分页兜底**：

- 页面滚动阶段保持原有逻辑不变（真人动作、响应拦截、风控基线）。
- 当检测到「已到底 + 连续无新响应 + 接口仍 `has_more=True`」时，
  从最后一条响应提取 `offset`（最后一条动态的 `id_str`），
  用 `page.evaluate` 在页面上下文里直接发 `fetch` 请求调用 `feed/space` 接口。
- API 请求复用浏览器 cookie、指纹、wbi 签名，不自行构造签名、不引入 httpx 直连。
- API 分页阶段持续翻页直到 `has_more=False` 或触顶 `max_feed_responses` 硬上限。

风控基线不变：专用小号、单浏览器实例、操作间隔随机 2–8 秒、只读取不写入、
熔断冷却 24h。API 分页的请求频率与页面滚动保持一致。

### 备选方案

- 接受分页限制，只抓最近内容：archive 功能名不副实，拒绝。
- 改用 httpx 直连 + 自维护 wbi 签名：回到 ADR-0003 的老路，签名失效风险高，拒绝。
- 模拟点击「加载更多」按钮：B 站空间页没有该按钮，纯滚动加载，拒绝。

## 后果

- 收益：`archive` 可完整回溯任意年份的内容，实测 2026 年 1–10 月共 514 条
  （62 视频 + 452 图文），1–7 月内容全部补齐。
- 成本 / 风险：API 分页比页面滚动更快，但仍在同一浏览器会话内，风控暴露面不变；
  `page.evaluate` 执行 fetch 属于标准浏览器能力，不引入新的检测面。
- 配套措施：`archive` 命令的 `--max-scrolls` 参数同时限制页面滚动次数和 API 分页次数；
  解析层 `parse_feed_page` 无需改动，API 响应与页面拦截响应格式完全一致。
