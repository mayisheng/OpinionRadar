# api-probe：平台接口结构探测对拍

## 目的

目标平台的私有接口没有稳定文档，字段位置随版本漂移
（实例：详情接口正文在 `major.opus.summary.text`，而列表预览用 `summary_text`，
凭文档猜会全部落空）。本技能固化
「拦截真实响应 → 落盘核对 → 修正解析器 → fixture 对拍」的闭环，
保证解析器永远与真实响应一致，适用于任何以响应拦截方式接入的 Connector。

## 触发时机

- 解析器输出的某字段总是空 / 报「接口结构可能已变化」。
- 新增拦截目标前需要确认响应结构。
- 解析器单测（fixture 对拍）与线上行为不符。

## 执行步骤

1. **写临时探测脚本到 /tmp**（绝不入仓库），模板要点：
   - 复用 `opinion_radar.config` 的浏览器配置与 `data/browser-profile`
     持久化 profile（带真实登录态，避免未登录响应结构不同）；
   - `page.on("response")` 按 URL 片段标记拦截（标记常量定义在
     `src/opinion_radar/collectors/<平台>/` 解析器模块顶部），
     `response.json()` 取原始 JSON 落盘到 `/tmp/*.json`；
   - 等待必须用 `page.wait_for_timeout`，**禁止 `time.sleep`**
     （同步 API 下会阻塞事件分发，响应永远拦截不到）；
   - 页面停留几秒确保目标请求发出，随后关闭上下文。
2. **用 `uv run python` 执行**（仓库环境里有 playwright 依赖），
   对 1~2 条代表性内容探测即可，不要批量访问（风控）。
3. **核对字段**：逐层打印真实 JSON 的 keys 与值，确认目标字段的真实位置、
   新旧字段并存情况；以真实响应为准，不以任何文档 / 记忆为准。
4. **修正解析器**：改对应平台的解析函数，
   新旧字段并存时取先非空者；解析逻辑只动解析器，浏览器层不动。
5. **fixture 对拍**：把脱敏后的响应写入对应平台的
   `tests/fixtures/<平台>/*.json`（假 ID、假正文、假图片 URL，
   不含任何真实博主内容），补/改单测对拍。
6. **验证**：`make lint && make test` 全绿后，删除 /tmp 临时脚本与原始响应。
7. 向用户报告：字段真实位置、修正点、涉及文件。

## 合规约束

- 拦截到的原始响应含真实内容，只允许落 /tmp 临时核对，**不得写入仓库、
  不得作为 fixture、不得粘贴到任何远程位置**。
- fixture 一律脱敏（假数据），沿用 tests/fixtures/ 现有惯例。
- 探测仅限少量样本（1~2 条），遵守 content-collect 的风控基线。

## 边界

- 探测发现链路本身的问题（登录失效、风控）→ 转 [content-collect](../content-collect/SKILL.md) 处理。
- 探测结论引出架构级取舍（如换接口、换方案）→ 用 [archive-adr](../archive-adr/SKILL.md) 归档。
